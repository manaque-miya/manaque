仮想記憶とは何か

木村さん（IT企業エンジニア1年目）が「RAM 8 GB なのにブラウザ・IDE・Slack を全部開いたら重くなった」と先輩に相談したところ、「スワップが多発してスラッシングに近い状態だよ」と言われた。仮想記憶の仕組みを理解した木村さんは、タスクマネージャで「コミット済みメモリ」を確認する習慣が付いた。

「物理メモリ（RAM）よりも大きな仮想アドレス空間をプロセスに提供し、必要な部分だけ物理メモリに置く仕組み」が仮想記憶だ。OS と CPU 内の MMU（Memory Management Unit）が協力して、プログラムが扱う仮想アドレスを物理アドレスに変換する。

💡 ポイント: 仮想記憶のポイントは「プログラムは物理メモリの実際の容量を意識せず大きなアドレス空間を使える」こと。4 GB の RAM しか搭載していなくても、OS が仮想的に 16 GB のように見せることができる。

主記憶が不足すると OS が使用頻度の低いページをディスク（スワップ領域）に一時退避させ、必要になったとき物理メモリに戻す。この操作をスワッピングと呼ぶ。

仮想記憶の仕組み

`` プロセス（仮想空間） 物理メモリ（RAM） 0x00000000 ┌──────────────┐ ┌──────────┐ ページテーブル │ ページA（物理）│ │ページA │──────────────→ │ │ │ページB │──────────────→ │ ページC（物理）│ │ページC │──────────────→ │ │ │ページD │──× ─────────→ スワップ（ディスク） └──────────┘ └──────────────┘ ``

⚠️ 間違いやすいパターン: 「仮想記憶はメモリを物理的に増設する仕組み」は誤り。あくまで「大きく見せる」ソフトウェア的な仕組みで、ディスクは主記憶の代わりではなくあくまで補助だ。スワップを多用すると ディスク I/O が大量発生し、「スラッシング」と呼ばれる性能劣化を引き起こす。

ここが試験のキモ ✅

  • ✅ 仮想記憶 = 物理メモリより大きい仮想アドレス空間を提供する OS の仕組み
  • ✅ ページング（固定サイズ分割）とセグメンテーション（可変サイズ分割）の 2 方式
  • ✅ ページフォルト = アクセス先ページが物理メモリにない → ディスクから読み込む
  • ✅ スラッシング = ページフォルトが多発してほとんどの時間をスワッピングに費やす状態
  • ✅ TLB（Translation Lookaside Buffer）= ページテーブルのキャッシュ

ページフォルトとスラッシング

プロセスが参照しようとした仮想ページが物理メモリにないとき、ページフォルトという割り込みが発生する。OS はディスクからそのページを読み込み（ページイン）、必要に応じて既存のページを追い出す（ページアウト）。1 回のページフォルトはミリ秒単位の遅延をもたらすため、ページフォルトが多発する状況（スラッシング）ではシステム性能が激しく低下する。

対策として「ワーキングセット（プロセスが頻繁に使うページ群）を物理メモリに常駐させる」管理や、物理メモリの増設がある。

🎯 試験対策：仮想記憶の重要ポイント

「基本情報技術者 過去問」では「仮想記憶の目的」「ページフォルトの説明」「TLB の役割」が選択問題で頻出だ。

アドレス変換の流れを一度整理しておく。プログラムが仮想アドレスを生成 → TLB を参照（TLB ヒットなら即物理アドレス確定）→ TLB ミスならページテーブルを参照 → ページが物理メモリになければページフォルト発生 → OS がディスクからロード、という流れだ。

「基本情報技術者 午前・午後・独学」でこの分野を学ぶなら、仮想記憶・ページング・TLB・ページフォルト・スラッシングを1セットで覚え、何時間か集中して図を描きながら整理するのが定着の近道だ。
