テストマトリクスとは？

テスト対象（機能・条件）を縦横の表に並べ、「どの組み合わせを試したか」を一目で把握する手法。

🎬 こんなシーンを想像
新しいECサイトのテストを担当したあなた。「ブラウザ（Chrome・Safari・Firefox）×OS（Windows・Mac・iOS）」の全組み合わせを表にして、どれをテスト済みか一目でわかるようにした。
テスト漏れなし、報告もラクラク。
…この「組み合わせを表にする手法」の名前は？
📋 テストマトリクスの例
ブラウザ＼OS Windows Mac iOS Android
Chrome ✅ OK ✅ OK ✅ OK ❌ NG
Safari — 未 ✅ OK ✅ OK — 未
Firefox ✅ OK ✅ OK — 未 — 未

↑ このような表で「どのセルが未実施か」「NGがどこか」が一目でわかる

🗺️ テストマトリクスの作り方
① テスト対象の「軸」を決める
縦と横に何を並べるか決める。例：縦＝機能（ログイン・検索・カート）、横＝デバイス（PC・スマホ・タブレット）
▼
② 全組み合わせのセルを作る
縦×横の全セルに「テスト項目番号」か「実施予定」を入れる。これが「テスト設計の完了」を意味する。
▼
③ テスト結果を埋める
実施したセルに OK・NG・未実施を記録。空欄や NG が残っていれば「テスト漏れ」「不具合あり」が一目でわかる。

目的は「網羅性の確認」。抜けが見えること＝テストマトリクスの存在価値。

⚠️ ひっかけ注意ポイント
デシジョンテーブルとの違い
デシジョンテーブルは「条件の組み合わせ→動作を整理する表」（論理的な正しさを検証）。テストマトリクスは「何を・どの環境でテストしたかを管理する表」（網羅性の確認）。目的が違う。
テストマトリクス＝全組み合わせを実施する？
必ずしも全組み合わせを実施するわけではない。「どこをテストすべきか見える化」が目的。実施優先度を絞るための判断材料にもなる。
「直交表」との混同に注意
直交表は組み合わせを統計的に最小化するテスト設計手法（全組み合わせをカバーしつつ件数を減らす）。テストマトリクスとは別物。
判断のコツ
「テスト項目を縦横の表に整理」「漏れがないか確認」「環境×機能の組み合わせ」→ テストマトリクス一択。
🧠 覚え方（無理やりゴロ）
「マトリクス＝マス目のチェックシート」
縦横のマス＝全組み合わせ。埋まってないマスがテスト漏れ！

「マト（的）を外すな！マトリクスで網羅」
テスト漏れ＝的（まと）を外すこと。マトリクスで全セルを「的」にして撃ち抜く！
