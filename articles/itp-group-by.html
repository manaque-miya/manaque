SQL の GROUP BY 句とは？

行をグループにまとめて、集計関数（COUNT・SUM・AVG）と組み合わせる SQL の核心。

🎬 こんなシーンを想像
社内の売上データベースを担当しているあなた。上司に「部署ごとの売上合計を出してほしい」と頼まれた。テーブルには 1000 行のデータがある。
→ 「部署ごと」にまとめて合計する＝これが GROUP BY の出番！
📊 GROUP BY の仕組み（図解）

バラバラな行を「同じ部署」でまとめ、合計・件数などを一気に計算する。

📝 SQL の書き方（実行順序）
SELECT 部署, SUM(売上) -- ③ 出力列を選ぶ
FROM 売上テーブル -- ① テーブルを指定
WHERE 年度 = 2024 -- ② 行を絞る（集計前）
GROUP BY 部署 -- ④ グループ化
HAVING SUM(売上) >= 100 -- ⑤ グループを絞る（集計後）
ORDER BY SUM(売上) -- ⑥ 並び替え;
WHERE ＝「集計の前」に行を絞る
「2024年のデータだけ使う」などの条件。集計関数（SUM・COUNT）は使えない。
▼
GROUP BY ＝ 行をグループにまとめる
指定した列の値が同じ行をまとめる。複数列を指定することも可能（GROUP BY 部署, 年）。
▼
HAVING ＝「集計の後」にグループを絞る
「合計が100万以上のグループだけ残す」など。集計関数を条件に使える＝WHERE と違う点。
⚠️ ひっかけ注意ポイント
WHERE と HAVING の混同
WHERE は集計前の行フィルタ（SUM などは書けない）。HAVING は集計後のグループフィルタ（SUM などが書ける）。試験では「どちらを書けるか」が頻出。
SELECT に書ける列は GROUP BY した列だけ
GROUP BY 部署 なら SELECT に書けるのは「部署」と集計関数だけ。「氏名」を SELECT に書くとエラー＝1グループに複数の氏名があり一意にならないため。
実行順序の誤解
SQL は「書く順」と「実行順」が違う。実行順は FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY。WHERE を GROUP BY の後に書けばよい、は誤り。
🧠 覚え方（無理やりゴロ）
「グルーピー（GROUP BY）は集合後しか入れない（HAVING）」
グルービーな人はコンサート（集計）のあとにVIP室（HAVING）に入る。
入口（WHERE）で止めるのは普通の人だけ。

WHERE ＝ 集計「前」のふるい（集計関数 NG）
HAVING ＝ 集計「後」のふるい（集計関数 OK）
