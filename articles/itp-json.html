JSONとは？

人間にもコンピュータにも読みやすい、データ交換の共通言語。WebAPIの事実上の標準フォーマット。

🎬 こんなシーンを想像
スマホアプリが天気情報サービスに「東京の明日の天気を教えて」とリクエストした。サーバーはJSON形式でデータを返してくる。
「気温」「天気」「湿度」がキーと値のペアで整然と並んでいる。
…このデータ形式が JSON。
🔧 JSONの基本構造
{ name: 田中太郎, age: 28, isStudent: false, skills: [Java, Python], address: { city: 東京 } }
name:田中 文字列/数値/真偽値 配列 [Java,Python] 複数値を[ ]でまとめる ネスト address:{…} { }の中に{ }を入れる 全体を { } で囲む＝オブジェクト キーは必ず文字列（ダブルクォート） 軽量・人間が読める・言語非依存
🔄 WebAPIでの使われ方
① クライアント（アプリ）がリクエスト送信
スマホアプリやWebブラウザが「このデータをください」とHTTPリクエストを送る。
▼
② サーバーがJSONで応答
サーバーはデータをJSON形式に変換して返す。文字ベースなので人間が目で読める。
▼
③ クライアントがJSONを解析して表示
アプリがJSONを読み取り、画面に表示する。どの言語でも同じJSONが扱える。
⚖️ XMLとの違い
比較項目JSONXML
書き方キーと値のペア {"key":"value"}タグで囲む <key>value</key>
データ量少ない（タグが不要）多い（開閉タグ分増える）
読みやすさシンプル冗長になりやすい
主な用途WebAPI・Webアプリ設定ファイル・文書交換
現在の主流◎ WebAPIで事実上の標準△ 特定分野で使用
⚠️ ひっかけ注意ポイント
「JSONはJavaScript専用」は間違い
JSONはJavaScript Object Notationが語源だが、今はPython・Java・Rubyなどあらゆる言語で使える汎用フォーマット。JavaScriptだけではない。
「JSONの文字列はシングルクォート可」は間違い
JSONの仕様ではキーも文字列値も必ずダブルクォート（"）。シングルクォートは不可。プログラムでは使えてもJSONとしては無効。
XMLとの混同に注意
JSONは{}と[ ]で構造を表す。XMLはタグ（<>）で表す。「タグで囲む形式」と言ったらXML。
判断のコツ
「WebAPIのデータ交換」「軽量」「{キー:値}」のキーワードが出たら → JSON。
🧠 覚え方（無理やりゴロ）
「ジェー・ソン、カギカッコ持参」
J=JavaScript / S=Script / ON=Object Notation
キーは必ずダブルクォート（カギカッコ＝"）持参

{キー: 値}の形が基本。
カギカッコ（"）なしのキーはJSONじゃない！
