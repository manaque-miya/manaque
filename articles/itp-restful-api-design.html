API設計原則（RESTful）とは何か

RESTful APIの問題で差がつくのは、HTTPメソッドとリソース設計の対応を正確に覚えているかどうかだ。GETとPOSTの違いから始まり、REST制約の原則まで体系的に理解しておく必要がある。

HTTPメソッドとCRUD対応

HTTPメソッドCRUD操作用途冪等性
GETReadリソース取得○（何度実行しても同じ結果）
POSTCreateリソース新規作成✗（実行ごとに新規作成）
PUTUpdate（全体置換）リソース全体更新○
PATCHUpdate（部分更新）リソースの一部更新△
DELETEDeleteリソース削除○

RESTの6制約

制約概要具体例
クライアント・サーバ分離UIとデータ保存を分離SPA + APIサーバ
ステートレスセッション状態をサーバに持たないJWTトークン認証
キャッシュ可能レスポンスにキャッシュ可否を明示Cache-Controlヘッダ
統一インタフェース統一されたURL・メソッドで操作/users/123 + GETで取得
階層化システムプロキシ・ゲートウェイを透過的に挟めるAPIゲートウェイ
コードオンデマンドクライアントにコードを送って実行（任意）JavaScript配信

💡 ポイント: RESTの最重要原則はステートレスだ。サーバーがクライアントのセッション状態を保持しないため、水平スケールが容易になる。認証にはJWTなどのトークンをクライアント側で保持し、毎リクエストで送信する。これがRESTfulなAPIが大規模システムで採用される根本理由だ。

⚠️ 間違いやすいパターン:

- 誤：POSTは冪等性があるため、同じリクエストを複数回送っても問題ない

- 正：POSTは冪等でない。同じリクエストを複数回送ると複数のリソースが作成される。べき等性があるのはGET・PUT・DELETE

ここが試験のキモ

1. GET＝取得・POST＝作成・PUT＝更新・DELETE＝削除

2. ステートレス＝サーバにセッション情報を持たない

3. URIはリソースを表す名詞（/users/123）、操作はメソッドで表現

4. APIキーやJWTによる認証はステートレスの実現手段

混同しやすい用語との違い

用語内容区別ポイント
RESTアーキテクチャスタイル制約の集合体
RESTful APIREST原則に従ったAPIHTTP + URI設計
SOAPXMLベースのプロトコルエンタープライズ向け
GraphQLクエリ言語ベースのAPI必要なデータのみ取得

🎯 試験対策：API設計原則（RESTful）の重要ポイント

「RESTful APIにおいてリソースを削除する操作に使うHTTPメソッドはどれか」が典型問題。答えはDELETE。また「ステートレスとはどういう意味か」という正誤問題では「サーバが前回のリクエスト情報を記憶しない」が正解で「クライアントが状態を持たない」は誤り（逆）。
