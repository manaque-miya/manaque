Git（バージョン管理）とは何か

Gitは分散型バージョン管理システムであり、ファイルの変更履歴をローカルリポジトリに保存しながら、複数人が並行して同じコードベースを編集できる仕組みを提供する。2005年にLinuxカーネルの開発のためにLinus Torvaldsが開発した。

💡 ポイント: Gitは「無限に戻れる保存ポイント」を持つタイムマシンのようなもので、好きな時点のコードに戻ったり、複数の作業を並行して進めたりできる。

Gitの主要概念

概念説明操作コマンド例
リポジトリ変更履歴を保存する場所（ローカル・リモート）git init / git clone
コミット変更のスナップショット（単位）git commit
ブランチ作業の分岐（機能開発・修正用）git branch / git checkout
マージブランチを統合するgit merge
プルリクエストマージ前のコードレビュー依頼GitHub/GitLab のUI

GitHub・GitLabはGitリポジトリをクラウドでホスティングするサービスで、Gitそのものとは区別する。ブランチ戦略にはGitFlow（main/develop/feature/release/hotfix）とGitHub Flow（mainとfeatureだけ）があり、チームの規模やリリース頻度に応じて選択する。コンフリクト（競合）は同一箇所を複数人が編集した際に発生し、手動解決が必要になる。

⚠️ 間違いやすいパターン: 「Git＝GitHub」と混同する誤りが多い。GitはツールでGitHubはGitを使ったホスティングサービスであり、別物だ。

ここが試験のキモ

  • ✅ Gitは「分散型」バージョン管理システム（中央集権型のSVNと対比される）
  • ✅ コミット・ブランチ・マージが基本操作の三本柱
  • ✅ GitHubなどのホスティングサービスはGitを利用したサービスであってGit本体ではない

混同しやすい用語との違い

用語特徴試験での見分け方
Git分散型バージョン管理ツール本体ローカルでも完結できる点がキー
GitHubGitリポジトリのクラウドホスティングサービス名・共同開発プラットフォーム
SVN中央集権型バージョン管理サーバー依存・分散でない点がキー

🎯 試験対策：Git（バージョン管理）の重要ポイント

Gitの問題で問われるのは「分散型」という特徴と、コミット・ブランチ・マージの基本概念だ。

試験ではバージョン管理の目的（変更履歴の記録・過去状態への復元・並行開発の支援）を問うパターンが多い。また「分散型と集中型の違い」を問う選択問題も頻出で、Gitは「ローカルに完全な履歴を持つ」点が集中型のSVNとの最大の違いだと答えればよい。CI/CDパイプラインの文脈でも「ソースコード管理にはGitを使う」という知識が前提として問われる。

覚え方は「Git＝分散・ローカル・コミット」「GitHub＝クラウドサービス・共同開発」。混同注意は「GitとGitHub」と「バージョン管理とバックアップ」で、バックアップは過去状態の保存だがバージョン管理は変更差分と履歴も管理する点が異なる。
