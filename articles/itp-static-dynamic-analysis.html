静的解析・動的解析とは何か

静的解析はプログラムを実行せずにソースコードを検査してバグや品質問題を検出する手法、動的解析はプログラムを実際に実行した状態でメモリ・パフォーマンス・動作を検査する手法だ。両者を組み合わせることでソフトウェア品質の多面的な確保が可能になる。

💡 ポイント: 静的解析は「設計図を見て欠陥を探す」、動的解析は「実際に動かして挙動を観察する」イメージだ。

静的解析と動的解析の比較

観点静的解析動的解析
実行の有無実行しない実行する
検出対象コーディング規約違反・潜在バグ・セキュリティ脆弱性メモリリーク・パフォーマンス問題・実行時エラー
タイミングコーディング中〜ビルド時テスト時〜本番監視
代表ツールSonarQube, ESLint, CheckmarxValgrind, New Relic, Dynatrace
コスト低い（早期発見）高い（環境準備が必要）

静的解析はCI/CDパイプラインに組み込み、コードプッシュのたびに自動実行するのが現代の標準だ。セキュリティ用途ではSAST（Static Application Security Testing）とも呼ばれ、SQLインジェクション・XSSなどの脆弱性パターンをコード段階で検出できる。動的解析のセキュリティ版はDAST（Dynamic Application Security Testing）で、実際にアプリを動かして外部から攻撃を試みる。

⚠️ 間違いやすいパターン: 静的解析と単体テストを混同する誤りがある。単体テストはコードを実行して結果を検証する「動的」な手法であり、静的解析とは別物だ。

ここが試験のキモ

  • ✅ 静的解析＝実行せずにコードを検査、動的解析＝実行して検査
  • ✅ SASTが静的、DASTが動的のセキュリティ版
  • ✅ 静的解析はコーディング規約・脆弱性の早期発見に有効

混同しやすい用語との違い

用語特徴試験での見分け方
静的解析実行なし・コードを直接検査「実行せずに」がキーワード
動的解析実行あり・実際の挙動を検査「実行中に」「ランタイム」がキーワード
単体テストコードを実行して期待値と照合テスト結果の検証がキーワード

🎯 試験対策：静的解析・動的解析の重要ポイント

試験では静的解析・動的解析を「プログラムを実行するかどうか」という形で問う。

「プログラムを実行せずに品質を検査する手法はどれか」という問いに静的解析と答えられれば十分だ。セキュリティ分野との連携では「SASTはいつ実行するか」という問いも出る。正解は「コーディング時またはCIパイプライン中（ビルド前後）」だ。静的解析の利点として「早期発見によりバグ修正コストが低い（バグは後工程ほど修正コストが指数関数的に増加する）」という知識も問われることがある。

覚え方は「静的＝静止・実行なし」「動的＝動いている・実行あり」。混同注意は「SAST（静的）とDAST（動的）」のSとDの頭文字に注目すること。
