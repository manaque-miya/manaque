ポリモーフィズムとは何か

「同じ名前のメソッドが、呼び出されるオブジェクトの型によって異なる処理を実行する性質」がポリモーフィズム（Polymorphism、多態性）だ。「多様な形をとる能力」という語義どおり、同じインタフェースで異なる実装を切り替えられる。OOPの3大要素の1つで、拡張性と保守性を高める最重要機能だ。

💡 ポイント: ポリモーフィズムの本質は「呼び出し元が型を意識しなくていい」ことだ。Animal 型のリストに Dog・Cat・Bird を混在させ、全部に speak() を呼ぶだけで各自が「ワン」「ニャン」「チュン」と答える。

「基本情報技術者 過去問」ではポリモーフィズムを使ったプログラムのトレースが科目B（旧午後）で頻出だ。実行時にどのクラスのメソッドが呼ばれるかを正確に追う練習が得点直結する。「基本情報技術者 独学」では動物クラス階層を題材に実際に書いて動かすことで理解が定着する。

ポリモーフィズムの2種類

種類タイミング実現手段例
オーバーライド（実行時多態）実行時に決定継承＋オーバーライド親のspeak()を子で再定義
オーバーロード（コンパイル時多態）コンパイル時に決定同名メソッドの引数違いadd(int,int) と add(double,double)

⚠️ 間違いやすいパターン: 「オーバーライド（継承先での再定義）」と「オーバーロード（同名・引数違い）」は別物だ。ポリモーフィズムの文脈で「同じ名前で動作が変わる」本命はオーバーライドの方。オーバーロードはコンパイル時に解決されて実行時に型で切り替わる動的な多態ではない。

ここが試験のキモ ✅

  • ✅ ポリモーフィズム＝「同じメソッド名で異なる処理を、型に応じて実行する性質」
  • ✅ 実行時多態：親クラス参照で子クラスのオーバーライドされたメソッドが呼ばれる
  • ✅ 「基本情報技術者 過去問」では「変数の型と実インスタンスの型が異なるときにどのメソッドが呼ばれるか」が頻出
  • ✅ ダウンキャスト：親型変数を子型に明示変換（ClassCastException のリスクあり）
  • ✅ 「基本情報技術者 午前午後」双方で概念問題とトレース問題が出る

プログラムトレース例

```java class Animal { void speak() { System.out.println("..."); } } class Dog extends Animal { @Override void speak() { System.out.println("ワン"); } } class Cat extends Animal { @Override void speak() { System.out.println("ニャン"); } }

Animal a = new Dog(); // Animal型変数にDogインスタンス a.speak(); // 出力：「ワン」← Dog のメソッドが呼ばれる ```

変数の型（Animal）ではなく、インスタンスの実際の型（Dog）でメソッドが決まる。これが実行時ポリモーフィズムの核心だ。

🎯 試験対策：ポリモーフィズムの重要ポイント

「基本情報技術者 科目B・午後問題」では、上記のようなコードトレースが典型出題だ。「変数 a に対して speak() を呼んだとき出力されるのはどれか」という問いで、「Animal の ...」と「Dog の ワン」が選択肢に並ぶ。実インスタンスの型を見て答える。

「ポリモーフィズム とは」の直問では「同一のメソッド呼び出しがオブジェクトの実際の型に応じて異なる処理を実行する性質」が正答文になる。「親クラスのメンバを子クラスに引き継ぐこと」（継承）は誤りのパターンだ。

「基本情報技術者 過去問・午前午後・独学・何時間」取り組む場合でも、ポリモーフィズムはコレクション（配列・リスト）に異なる型のオブジェクトを入れてループで処理する例を自分で書くことで体感できる。
