配列（アレイ）とは？

同じ種類のデータを番号付きで並べて一括管理するデータ構造。
「引き出しに番号を振って、まとめて整理する棚」です。

🎬 こんなシーンを想像
クラス全員の試験点数を管理するプログラムを作ることになった。生徒が40人いるとき、変数を40個作る？
そんなときに使うのが配列。「scores[0]＝85点、scores[1]＝90点…」と番号を振ってまとめて管理できる。
…これが配列の力！ 大量データを番号で一括管理。
🔍 配列の構造（図解）

配列の特徴は3つ：① 同じ型のデータをまとめる ② インデックス（添字）で個別アクセス ③ インデックスは 0 から始まる（0始まりが重要）

📋 1次元配列 vs 2次元配列
1次元配列 — 1本の列
scores[0]〜scores[4] のように、1方向に並べる。数値・文字列のリスト管理に使う。アクセスは scores[インデックス] の1つの数字。
▼
2次元配列 — 表（縦×横）
table[行][列] のように、縦・横の2方向で管理。クラス×教科の点数表など表形式のデータに対応。アクセスは2つの数字が必要。
▼
多次元配列 — さらに次元を増やせる
3次元以上も論理的には可能だが、ITパスポートの範囲では1次元・2次元を理解しておけば十分。
// 1次元：点数の列
scores[0] = 85; scores[1] = 90;

// 2次元：クラス×教科
table[0][0] = 85; // 1組・国語
table[0][1] = 90; // 1組・数学
⚠️ ひっかけ注意ポイント
「インデックスは1から始まる」は誤り
多くのプログラミング言語でインデックスは0から始まる。要素が5個なら [0][1][2][3][4]。最後の要素は scores[4]（5ではない！）。
配列 vs 変数の混同
変数は1つの値しか持てない。配列は同じ名前で複数の値を番号付きで管理できる。大量データには配列を使う。
配列のサイズは宣言時に決まる（多くの言語）
C言語など静的型付け言語では、配列のサイズ（要素数）は宣言時に決める必要がある。後から変えられない点に注意。
🧠 覚え方（無理やりゴロ）
配列＝「番号付き引き出しの棚」
scores[0]・scores[1]・scores[2]…と引き出し（インデックス）に番号を振って並べる棚！

0から始まる＝「ゼロ番から」
「最初の引き出しは1番」ではなく「0番」。
5個の引き出しは 0・1・2・3・4 ＝最後は4番！
