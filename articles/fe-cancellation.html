桁落ちとは何か

「ほぼ等しい2つの数を引き算したとき、有効桁数が大幅に失われる現象」が桁落ちだ。値としての差は小さくても、コンピュータ内部では有効桁が激減して後続の計算精度が崩れる。数値計算分野では回避が必須のトラブルだ。

💡 ポイント: 桁落ちは「引き算で意味のある桁が消える」現象。1.234567 - 1.234560 = 0.000007 で、有効桁は7桁から1桁に激減する。

木村さん（IT企業エンジニア1年目）が二次方程式の数値解法を実装したとき、ほぼ同じ値の引き算で結果が大きくズレた。「それ桁落ちだよ。有理化して式を変形しないと」と先輩に教わり、式の変形がバグ対策になることを初めて知った。

7桁精度で 1.234567 と 1.234560 を保持している場合、引き算の結果 0.000007 はほぼ精度ゼロの「ノイズのみ」になる。元の7桁の下の誤差が引き算で表面に出てくるのが桁落ちの本質だ。

桁落ちの具体例と回避策

問題のある計算： a = 1.000001 b = 1.000000 差 = a - b = 0.000001 ← 有効桁が1桁に激減

回避策（式変形）： 二次方程式 x^2 - 2bx + c = 0 の根 解の公式：x = (2b ± √(4b²-4c)) / 2 = b ± √(b²-c) b が大きく c が小さいとき、b - √(b²-c) で桁落ちが起きる → 有理化：(b - √(b²-c)) × (b + √(b²-c)) / (b + √(b²-c)) = c / (b + √(b²-c)) に変換して桁落ちを回避する

⚠️ 間違いやすいパターン: 「情報落ち（大小差の大きい加算）」と「桁落ち（近い値の引き算）」は発生条件が逆になる。情報落ちは足し算で小さい値が消え、桁落ちは引き算で有効桁が消える。

ここが試験のキモ ✅

  • ✅ 桁落ち＝「近い値の引き算で有効桁が激減する現象」
  • ✅ 「基本情報技術者 過去問」では「桁落ちが起こる演算はどれか」という形で出題
  • ✅ 発生条件：a ≒ b のときの a − b が危険
  • ✅ 回避策：有理化・式変形で引き算を避ける
  • ✅ 「基本情報技術者 独学」では情報落ちと対比させて同時に覚えると混同しにくい

数値計算での桁落ち回避

連立方程式のガウス消去法では、ピボット選択（最大絶対値の要素を選んで交換する「部分ピボット選択」）で桁落ちを減らす。積分では解析的に変換してから計算する手法が有効だ。

「基本情報技術者 科目B・午後問題」でアルゴリズムの精度問題として出題される場合、「なぜ計算精度が落ちるのか」の原因特定に桁落ちが正解になるケースがある。

🎯 試験対策：桁落ちの重要ポイント

「基本情報技術者 過去問」での出題形式は「次のうち桁落ちが発生するのはどれか」が典型で、選択肢には「(1.23456 - 1.23455) / 0.001 のような計算式が並ぶ。近い値の差が含まれている式を選ぶ。

「桁落ち とは」という直問では「浮動小数点演算において、近い値同士の減算により有効桁数が著しく減少する現象」が正答文になる。「除算で桁が落ちる」「加算で桁が落ちる」は誤りの選択肢パターンだ。

「基本情報技術者 勉強方法」として桁落ちは具体的な数値でトレースすると理解が速い。7桁の値から7桁の値を引いた結果の有効桁数を数えてみるだけで現象が直感的に把握できる。基本情報技術者の過去問・午前午後・独学・何時間の勉強時間でも「桁落ちが発生する演算はどれか」という選択問題は必ず練習しておくべき頻出パターンだ。
