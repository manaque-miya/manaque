情報落ちとは何か

「大きさが極端に異なる数値を加減算したとき、小さい側の情報が桁数制限で切り捨てられて失われる現象」が情報落ちだ。コンピュータの浮動小数点数は有効桁数に上限があるため、桁数が大きく違う数を足すと小さい方の情報が消えてしまう。

💡 ポイント: 情報落ちは「大きい数に小さい数を足しても変わらない」現象。1.0×10^10 + 1.0 ≒ 1.0×10^10 で 1.0 の情報が丸ごと消える。

木村さん（IT企業エンジニア1年目）が大量データの積算処理を書いたとき、最初に大きな値を足してから小さな値を積み上げたら合計がズレた。「足す順番が逆。小さい方から足さないと情報落ちするよ」と先輩に指摘され、計算順序が誤差に影響することを初めて知った。

64ビット倍精度浮動小数点の有効桁は 15〜16 桁程度だ。1.0e15 + 1.0 を計算すると、指数を合わせる際に 1.0 は下位にシフトされ、表現桁数を超えて切り捨てられる。結果は元の 1.0e15 と変わらない。

情報落ちの具体例と対策

``` 問題のある計算（合計を大きい順に足す）： sum = 1.0e15 sum += 1.0 → sum = 1.0e15（1.0が消える） sum += 1.0 → sum = 1.0e15（また消える） … 1.0e6回繰り返しても sum = 1.0e15のまま

対策（小さい順に足す）： sum = 0.0 sum += 1.0 を 1.0e6回繰り返す → sum = 1.0e6 sum += 1.0e15 → sum = 1.001e15（今度は情報が残る） ```

⚠️ 間違いやすいパターン: 「情報落ち＝桁落ち」という混同が多い。情報落ちは「大小差のある加算」で小さい値が消える現象。桁落ちは「近い値の引き算」で有効桁が消える現象。発生する演算の種類と方向が正反対だ。

ここが試験のキモ ✅

  • ✅ 情報落ち＝「大小差の大きい加減算で小さい側の情報が消える現象」
  • ✅ 対策：小さい値から順番に足す（累積させてから大きい値と合わせる）
  • ✅ 「基本情報技術者 過去問」では桁落ちとの区別問題が頻出
  • ✅ 「基本情報技術者 独学」では「大きい数に1を足しても変わらない」例を手計算で確認
  • ✅ 計算順序を変えるだけで誤差を大幅に低減できる点を覚える

情報落ちの実務的影響

数値積分（台形法・シンプソン法）で区間を細かく分割するとき、各微小区間の値が小さくなりすぎて積分値に反映されなくなる「情報落ち」が発生する。これを防ぐためにカハンの加算アルゴリズム（補正項を追加して累積誤差を抑える）が使われる。

「基本情報技術者 科目B・午後問題」で「次のアルゴリズムが正確な合計を求めるのに向いていない理由を述べよ」という形式で出題される場合、計算順序の問題として情報落ちが問われることがある。

🎯 試験対策：情報落ちの重要ポイント

「基本情報技術者 過去問」では「次の浮動小数点演算で情報落ちが発生するのはどれか」という形で選択肢から選ぶ問題が出る。10^10 + 10^-5 のような数量差が極端な加算が正解の選択肢になる。

「情報落ち とは」の直問では「絶対値の大きく異なる数値を加算したとき、絶対値の小さい数値の情報が失われる現象」が正答文になる。「引き算で起きる」は誤りのパターンだ。

「基本情報技術者 勉強方法」として情報落ちは「大きいのと小さいのを足したら小さいのが消えた」というイメージを固めたうえで、桁落ちと対比で整理するのが最短ルートだ。基本情報技術者の過去問・午前午後・独学・何時間の学習でも「桁落ちと情報落ちの区別」は頻出なので、対になる概念として必ずセットで覚えておく。
