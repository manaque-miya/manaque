ブレークポイントとは？

デバッグのときにプログラムを「ここで一時停止して！」と指示するための目印。バグ探しの必須テクニック。

🎬 こんなシーンを想像
プログラムを書いたあなた。計算結果がなぜかおかしい。プログラムは何百行もあって、どこでバグが起きているかわからない。そこで「怪しい行に目印をつけ、そこで実行を止めて変数の中身を確認する」ことにした。
…その「目印」が「ブレークポイント」。
🖥️ ブレークポイントのしくみ
1: result = 0 2: for i in range(10): 3: result = result + i * 2 ⬛ ブレークポイント設定 4: result = result + bonus ← ここで一時停止！ 5: return result
🗺️ ブレークポイントを使ったデバッグ手順
① 怪しい行にブレークポイントを設定
バグが起きていそうな行や、確認したい変数が使われている行を選んで目印をつける。
▼
② プログラムをデバッグモードで実行
ブレークポイントの行まで来ると自動で一時停止する。この時点での変数の値を確認できる。
▼
③ 変数の値・状態を検査してバグを特定
想定外の値が入っている変数を発見。「どこでおかしくなったか」の原因を突き止める。
▼
④ 実行を再開して次の確認ポイントへ
ステップ実行（1行ずつ進める）や次のブレークポイントまで実行して詳しく追う。
⚠️ ひっかけ注意ポイント
「ブレークポイント」と「損益分岐点（Break-Even Point）」の混同
デバッグの「ブレークポイント」はプログラムの中断点（テクノロジ系）。「損益分岐点」は財務・経営の概念（ストラテジ系）。Break-Even と Breakpoint は全く別物。
ブレークポイントはプログラムを「終了」させない
ブレークポイントで「一時停止」する。プログラムは終了していない。確認後は再開できる。「停止」と「終了」を混同しない。
ブレークポイントはデバッグの手法の一つ
デバッグには他にもステップ実行・トレース・ログ出力などがある。問題文で「プログラムを特定の行で一時停止する」と書かれたらブレークポイントを選ぶ。
🧠 覚え方（無理やりゴロ）
ブレーク＝「ブレーキ」をかける場所
「ブレーク（Break）」＝止まれ！ の「ブレーキ」、「ポイント」＝場所

「プログラムにブレーキランプを仕掛ける」
→ そこに来たら一時停止して変数を見る ＝ ブレークポイント
