APIセキュリティ（レートリミット）とは何か

APIセキュリティのレートリミットを答えるポイントは、「一定時間内のリクエスト数を制限することで、不正利用・過負荷・DoS攻撃を防ぐ仕組み」という定義と、その具体的な実装方式を把握することだ。

レートリミットの主要アルゴリズム

アルゴリズム概要特徴
固定ウィンドウ時間窓内のリクエスト数を制限窓の境界でバースト攻撃が可能
スライディングウィンドウ過去N秒のリクエスト数をリアルタイム計算より均一に制限できる
トークンバケットバケツにトークンを補充し1リクエスト1トークン消費バーストに一定程度対応可能
リーキーバケットリクエストをキューに溜め一定速度で処理安定した処理レートを保証

APIセキュリティの主要脅威と対策

脅威内容対策
DoS/DDoS大量リクエストで可用性を侵害レートリミット・WAF
ブルートフォース認証情報を総当たりログイン試行回数制限
スクレイピングAPIを通じたデータ大量収集レートリミット・CAPTCHA
APIキー漏洩キーを悪用した不正アクセスキーのローテーション・IPホワイトリスト
不正なデータ操作認可チェック漏れで他者データを操作オブジェクトレベル認可（OWASP API Top1）

HTTPレスポンスヘッダーでの通知

ヘッダー内容
X-RateLimit-Limit制限値（例：1000リクエスト/時間）
X-RateLimit-Remaining残りリクエスト数
X-RateLimit-Reset制限リセット時刻（UNIXタイム）
Retry-After429エラー時の再試行待ち時間

💡 ポイント: レートリミット超過時のHTTPステータスコードは429 Too Many Requestsだ。APIクライアントはこのステータスを受け取ったら指数バックオフ（1秒→2秒→4秒と待機時間を増やす）で再試行するのが設計上の基本だ。

⚠️ 間違いやすいパターン:

- 誤：レートリミットはDDoS攻撃を完全に防ぐことができる

- 正：レートリミットはDoS緩和に有効だが、大規模DDoSにはWAF・CDN・ISPレベルの対策が別途必要。レートリミットは「一人あたりの制限」でありボリューム攻撃への完全な防御にはならない

ここが試験のキモ

1. レートリミット＝時間当たりのリクエスト数上限設定

2. 429 Too Many Requests＝レートリミット超過のHTTPステータス

3. ブルートフォース対策にもレートリミット（ログイン試行制限）が有効

4. トークンバケット・固定ウィンドウなどの実装アルゴリズムが問われる場合あり

混同しやすい用語との違い

用語内容区別ポイント
レートリミット時間当たりのリクエスト数制限過負荷・DoS緩和
スロットリング処理速度の制御レートリミットに近い概念
クォータ一定期間の総使用量制限月間API呼び出し数上限等
WAFWebアプリケーションファイアウォール攻撃パターン検知・ブロック

🎯 試験対策：APIセキュリティ（レートリミット）の重要ポイント

「APIに大量のリクエストが送られた場合に429エラーを返す仕組みとして適切なものはどれか」→「レートリミット」。また「認証情報へのブルートフォース攻撃対策としてログイン試行回数を制限する仕組みはどれか」という問いにもレートリミット（ログイン試行制限）が該当する。
