JSON・XMLとは何か

JSON（JavaScript Object Notation）とXML（Extensible Markup Language）は、異なるシステム・言語間でデータを交換するための標準的なテキスト形式だ。JSONは2001年頃から普及したシンプルな形式で、現在のREST APIの標準データ形式。XMLは1998年にW3Cが策定した拡張性の高い形式で、企業の基幹システム連携・設定ファイルに広く使われる。

💡 ポイント: JSON は「軽量・人間が読みやすい」、XML は「構造が厳密・拡張性が高い」—モダンなWebはJSON、レガシー企業システムはXMLが多い傾向だ。

JSONとXMLの比較

項目JSONXML
可読性高い・シンプル冗長・タグが多い
データサイズ小さい大きい（開始・終了タグ）
主な用途REST API・設定ファイル企業システム連携・SOAP・HTML
対応言語ほぼ全言語ネイティブ対応ほぼ全言語対応（パーサー必要）
スキーマ定義JSON Schema（非標準的）XML Schema（XSD）で厳密定義可

JSONの構造例：{"name":"田中","age":30,"city":"Tokyo"}（キーと値のペア）

XMLの同等例：田中30Tokyo

⚠️ 間違いやすいパターン: HTMLはXMLの一種ではない（HTMLは独自規格、XMLベースはXHTML）。ただし「HTMLはXMLに似た構造を持つマークアップ言語」というレベルでは正しい。

ここが試験のキモ

  • ✅ JSONはREST APIの標準データ形式・軽量・シンプル
  • ✅ XMLは拡張性・厳密さが強み・SOAP/EDIなど企業システムに多い
  • ✅ CSV（カンマ区切り）もデータ交換形式の一つ（表形式データ向け）

混同しやすい用語との違い

用語特徴
JSON軽量データ交換形式（REST APIに使われる）
XML拡張性の高いマークアップ形式（企業連携・設定に使われる）
CSVカンマ区切りのシンプルな表形式（スプレッドシートデータ向け）

🎯 試験対策：JSON・XMLの重要ポイント

試験では「REST APIが使うデータ形式はどれか」→JSON、「EDIや企業間データ交換に使われる厳密な形式は」→XMLという対応問題が出る。また「JSONをパースして特定の値を取り出す」問題も出題されることがある。

マークアップ言語との関係では、HTML・XML・JSONの階層整理が問われる。「HTMLはWebページの構造を表すマークアップ言語、XMLはデータを表現する汎用マークアップ言語、JSONはオブジェクト表現を用いたデータ交換形式」という位置づけを理解する。

クラウドの設定ファイルとしてJSON・YAML（JSONの上位互換として普及）・TOMLが使われる点も近年の出題傾向だ。Dockerのcompose.yml、Kubernetesのマニフェストなどインフラコード化（IaC）との関連でデータ形式が問われることがある。
